    三条贯穿全文的计数约定

    ① 1 次乘加 = 2 FLOPs

    矩阵乘 (M×K)·(K×N) 需要 M·K·N 次"乘 + 加"，记为 2·M·K·N FLOPs。这是整个领域的事实标准，所以后文所有数字都是纯矩阵乘 FLOPs。

    ② 非矩阵乘算子单独列出

    Softmax、GELU/SiLU、RMSNorm、残差相加、RoPE 这些逐元素算子不计入矩阵乘 FLOPs，但在页面上单列——它们虽然计算量小，却是显存带宽杀手（每个元素都要读+写一遍）。

    ③ 精度 P 决定字节数

    参数量 N 与激活量都是"元素个数"，乘以 P 字节才是显存。同一个模型 fp32 与 int4 的权重占用相差 8 倍，而 FLOPs 完全不变——这就是量化的本质。

    ④ 权重共享与偏置

    本页对 GPT 系列默认 embedding 与 LM head 权重共享（少一份 V·d）；GPT-2 的 LayerNorm bias 与线性层 bias 被忽略，所以算出的 123.6M 比官方 124M 略小——误差来自 bias，不是公式错。

    02两个运行阶段：Prefill 与 Decode

    同一份权重、同一套算子，但计算形态完全不同——这是理解 LLM 推理性能的第一关键。

    Prefill（预填充 / 提示处理）

      把整段 prompt 的 S 个 token 一次性并行喂进去。M = B·S 很大，矩阵是"高瘦"的，算力吃满 → 计算密集（compute-bound）。

      Decode（自回归解码）

        每步只算 1 个新 token，M = B。矩阵退化成向量×矩阵，算术强度极低 → 显存带宽密集（memory-bound），算力利用率通常只有 1% 量级。

        结构层面的三个关键事实

        ① 残差流是贯穿全程的"主干道"

        图中两条左侧弧线就是残差连接。整个模型从头到尾维护着一条宽度恒为 d = 的主干，每个子层只"往主干上加东西"。这解释了为什么隐藏维 d 如此关键：它既是信息通道宽度，又是几乎所有矩阵乘 FLOPs 的平方来源。

        ② 只有第 ③ 步是全模型唯一的平方项

        注意力矩阵宽度等于已缓存 token 数 T = 。除它以外，所有节点的计算量都只随 M 线性增长。把长上下文的所有性能问题归结到这一个节点上，基本不会有遗漏。

        ③ 权重是"每一层一份"，KV Cache 是"每一 token 一份"

        Block 框内的权重有 L = 份独立副本，恒定不变；而第 ②③ 步写入的 KV Cache 随每个新 token 增长 1 份。前者决定模型能不能装下，后者决定能开多长的上下文、能并发多少用户。

        ④ 参数量只是一半的故事

        当前结构参数 ，权重 。但同一份权重在不同阶段的表现可以差两个数量级：Prefill 把算力打满，Decode 把带宽打满。看结构图时要同时问一句"这是在哪个阶段跑"。

            08Roofline：为什么 Decode 慢得离谱

            算术强度 (Arithmetic Intensity) = FLOPs ÷ 访存字节数。它落在脊点左侧就是带宽受限，右侧才是算力受限。

            带宽屋顶（越陡的斜线） 算力天花板（水平线） 当前 Prefill 工作点 当前 Decode 工作点 脊点 (Peak FLOPs / BW)
            指标PrefillDecode（单 token）解释

            批大小如何把 Decode 从带宽地狱里捞出来

            权重每个 token 只需读一次，但 KV Cache 是每序列各读一份。所以加大批大小 B：FLOPs 线性涨，权重访存不变 → 算术强度 ∝ B。这就是连续批处理（continuous batching）的物理依据。

            BFLOPs / token访存字节算术强度受限于单序列 tok/s

            09训练阶段的显存：为什么是推理的 10 倍以上
