## Decoder-only LLM 前向计算分解 · 交互式学习页面

产出：`decoder-only-llm-forward-pass.html`（单文件、零外部依赖，~91KB）

**用户诉求**：详细学习经典 decoder-only LLM 基础，分解每一步计算、列出参与矩阵、
统计中间结果的计算量与存储占用，理解不同阶段的资源消耗。

**交付形式**：交互式网页 + 多模型对比（用户二选一确认）：
可调参（层数/隐藏维/头数与 KV 头数/FFN 维/词表/精度/批大小/序列长/上下文长/硬件），
全页数字实时重算。

**页面结构**（10 节）：记号约定 → Prefill/Decode 两阶段 → 15 张逐步分解卡
（tokenizer→embedding→RMSNorm→QKV→拆头→RoPE→QKᵀ→softmax→AV→W_O→FFN→×L→
最终归一化→LM head→采样）→ FLOPs 汇总与 2N 法则校验 → 显存汇总与激活明细 →
KV Cache 专题 → Roofline → 训练显存 → 经典模型对照 → 10 条要点。

**核心公式（已验证与官方参数量一致）**

- 单层参数：MHA 注意力 4d² + FFN（GELU 2·d·d_ff 或 SwiGLU 3·d·d_ff）+ 2×norm
  - 关键洞察：d_ff 取 4d（GELU）或 8d/3（SwiGLU）时 FFN 矩阵乘 FLOPs 都恰为 16·M·d²
- 单层 FLOPs = 2·M·d·(d+2·d_kv) [QKV] + 4·M·T·d [QKᵀ+AV] + 2·M·d² [W_O]
  + FFN + 2·M·d·V [LM head]
- KV Cache = 2·L·d_kv·C·P 字节
- 校验：GPT-2 small 123.6M / GPT-2 XL 1.555B / LLaMA-7B 6.74B / 13B 13.02B /
  70B 68.98B / GPT-3 174.57B —— 全部对上（偏差来自被忽略的 bias）

**验证方法（可复用）**：用 Python 独立算一遍参数量公式对官方规模；用 Node + 轻量
DOM 桩 eval 页面脚本，检查缺失元素 id、各阶段渲染长度、边界输入不崩。
本次靠此法抓出两个真实缺陷：SVG 演示属性中的 `var(--x)` 不生效（图表会变黑，
必须换具体色值），以及 `hvLine→hLine` 笔误。

**关键数值对照（LLaMA-7B, bf16, A100）**
- Prefill S=2048：29.26 TFLOPs（2N 法则给 27.60），AI≈2171，计算受限，~93.8ms
- Decode C=2048：14.29 GFLOPs/token，AI≈0.98 vs 脊点 153 → 带宽受限，~7.1ms/token (140 tok/s)
- KV Cache 524 KB/token；fp16 权重 13.5GB；混合精度 Adam 状态 107.8GB（16 字节/参数）
- INT4 下 decode 权重 3.37GB、AI 升至 3.93 → 约 4× 加速（FLOPs 不变）
